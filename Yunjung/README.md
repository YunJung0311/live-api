# 비트 — Yunjung 음성 에이전트

가상의 인격을 반영한 페르소나를 가진 에이전트 만들기.
‘비트(BEAT)’는 세상을 힙합과 음악의 관점으로 받아들이는 음악 덕후 캐릭터입니다. 편하고 리듬감 있는 한국어로 일상을 음악에 비유하며, “스껄” 같은 추임새와 짧은 비트박스, 즉흥 랩을 자연스럽게 사용합니다. 기본 답변은 1~4문장으로 하고, 정확한 정보가 필요할 때는 정확성을 우선합니다.
Mac 브라우저의 마이크·스피커와 `gemini-3.1-flash-live-preview`를 사용합니다.

## 실행

Python 3.10 이상과 최신 Chrome을 권장합니다. 아래 명령은 저장소 루트(`live-api`)에서 실행합니다.

```bash
python3 -m venv Yunjung/.venv
Yunjung/.venv/bin/python -m pip install -r Yunjung/requirements.txt
Yunjung/.venv/bin/python Yunjung/server.py
```

`Yunjung/.env`에 다음 이름으로 실제 키를 저장합니다. 기존 키가 `GOOGLE_API_KEY` 또는 `API_KEY` 이름으로 저장되어 있어도 읽습니다. 여러 이름이 있으면 `GEMINI_API_KEY`를 우선합니다.

```dotenv
GEMINI_API_KEY=발급받은_API_키
```

`.env` 변경은 다음 대화 시작 시 반영됩니다. 화면의 API 키 입력란에 키를 넣으면 `.env`보다 우선해 이번 대화에 사용합니다. 비워두면 `.env`의 키를 사용합니다. 입력한 키는 로컬 서버로 전달되며 파일이나 브라우저 저장소에 저장하지 않습니다. 시작 시 입력란이 비워지므로 다음 대화에서 직접 입력한 키를 쓰려면 다시 입력합니다.

1. `http://localhost:8000/`에 접속합니다.
2. **대화 시작**을 누르고 마이크 권한을 허용합니다.
3. “안녕, 비트” 하고 말을 겁니다. 마이크 표시와 대화 자막을 확인합니다.
4. 비트이 답하는 중에도 말을 걸 수 있습니다. 서버의 인터럽트 이벤트를 받으면 현재 재생과 예약된 오디오를 모두 중단합니다.
5. **대화 종료**를 누르면 마이크, 재생과 연결을 정리합니다. 터미널 서버 종료는 `Ctrl+C`입니다.

8000 포트가 사용 중이면 `Yunjung/.venv/bin/python Yunjung/server.py --port 8001`로 실행하고 `http://localhost:8001/`에 접속합니다.

## 구현 내용

- 서버가 `Yunjung/.env`를 읽고 Gemini WebSocket 연결을 중계합니다. 모델과 시스템 지시문은 서버에서 지정합니다.
- AudioWorklet으로 마이크 입력을 모노 16kHz, PCM16 little-endian으로 변환해 32ms 단위로 전송합니다.
- 브라우저 AEC·소음 억제를 요청하며, 응답 중에도 마이크 입력을 유지합니다.
- 응답 형식의 샘플레이트에 맞춰 오디오를 순서대로 재생하고 자막을 표시합니다.
- 연결 지연, 권한 거부, 키 누락, 세션 만료와 종료를 안내합니다. 재시작은 새 세션이며 이전 대화를 복원하지 않습니다.
- 자막과 음성을 로컬 파일에 저장하지 않습니다. 대화 음성은 응답 생성을 위해 Google API로 전송됩니다.
- 로컬 주소에만 서버를 열고 지정된 화면 파일만 제공합니다. `.env`, 서버 소스와 가상환경은 HTTP로 제공하지 않습니다.

## 검증

실제 API 키를 사용하지 않는 테스트입니다. JavaScript 테스트는 Node.js 22 이상에서 실행합니다.

```bash
Yunjung/.venv/bin/python -m unittest discover -s Yunjung -p 'test_*.py' -v
node --test Yunjung/audio.test.mjs Yunjung/character.test.mjs
```

서버 테스트는 로컬 모의 WebSocket으로 모델 설정, PCM 중계, 복합 오디오·자막 이벤트, 인터럽트, 연결 정리, 키 누락·오류 비노출, 정적 파일 제한을 확인합니다. 오디오 테스트는 16/44.1/48kHz 입력 변환, PCM 범위, 예약 재생 취소와 재생 상태를 확인합니다.

실제 API 인증, 3턴 이상 대화, 마이크·스피커 에코 억제, 끼어들기 체감 지연과 페르소나 품질은 장치에서 추가 확인이 필요합니다. Raspberry Pi 및 여러 에이전트의 발언 순서 제어는 아직 구현하지 않았습니다.

## 문제 해결

| 증상 | 확인할 내용 |
| --- | --- |
| 키가 없다는 안내 | IDE의 `Yunjung/.env`를 저장했는지, 변수명이 맞는지 확인합니다. |
| Gemini 연결 실패 | 네트워크, 키의 유효성, 모델 접근 권한, API 할당량을 확인합니다. 키 노출을 막기 위해 API 원문 오류는 출력하지 않습니다. |
| 마이크 권한 거부 | 브라우저 사이트 설정에서 마이크를 허용하고 다시 시작합니다. |
| 스피커 소리에 스스로 응답 | 스피커 음량과 마이크 간격을 조정합니다. AEC 효과는 장치별로 다르므로 헤드폰으로 비교합니다. |
| 대화 도중 연결 종료 | 시작 버튼으로 새 대화를 엽니다. 자동 세션 복원은 지원하지 않습니다. |

구현 참고: [Live API WebSocket 가이드](https://ai.google.dev/gemini-api/docs/live-api/get-started-websocket), [메시지·인터럽트 규격](https://ai.google.dev/api/live).

## 마이크 없이 채팅하기

시작 전에 **채팅만**을 선택하고 **대화 시작**을 누릅니다. 이 모드에서는 마이크 권한을 요청하지 않습니다. 연결 후 메시지를 입력하고 **보내기** 또는 Enter를 누르세요. Shift+Enter는 줄바꿈이며 한 번에 2,000자까지 보낼 수 있습니다. 비트는 음성과 자막으로 답합니다.

마이크 모드에서도 메시지 입력란을 사용할 수 있습니다. 입력 방식을 바꾸려면 대화를 종료한 뒤 새 모드를 선택해 시작합니다. 입력한 메시지는 응답 생성을 위해 Google API로 전송되며 로컬 파일에 저장하지 않습니다.


## 비트 캐릭터 애니메이션

메인 패널의 보라색 스냅백 로봇은 `assets/beat-mascot.png` 원본 위에 SVG 눈을 겹쳐 표시합니다. 원본 이미지는 수정하지 않습니다.

- **대기:** 반쯤 뜬 눈, 느린 고개 끄덕임과 깜빡임.
- **듣기:** 귀를 기울이는 자세와 열린 눈. 마이크 입력 크기에 반응합니다.
- **응답 준비:** 메시지 전송 또는 발화 종료 추정 후, 눈이 한쪽을 바라보고 점 세 개가 순서대로 켜집니다. 이는 실제 모델의 내부 추론 상태가 아니라 응답 대기 표시입니다.
- **말하기:** 실제 재생 음량을 AnalyserNode로 읽어 몸의 움직임 크기를 조절합니다. 마지막 오디오가 끝날 때까지 말하기 상태를 유지하며, 끼어들면 재생과 동작을 함께 전환합니다.
- **연결 오류:** 움직임을 멈추고 연결 확인 상태를 표시합니다.

`character.js`의 마이크 발화 추정은 UI에만 사용하며, 기존 Gemini 발화 감지·PCM 전송·버퍼 취소에는 영향을 주지 않습니다. 응답 대기 추정은 15초 후 해제됩니다. 대화 종료 시 애니메이션 루프와 오디오 분석 노드를 정리합니다.

‘움직임 끄기’ 버튼으로 캐릭터 동작을 멈출 수 있고, 운영체제의 동작 줄이기 설정도 따릅니다. 이 경우에도 상태별 눈 모양과 상태 텍스트는 유지합니다. 새 이미지·모듈 경로를 추가했으므로 기존 서버는 한 번 재시작해야 합니다.
