# 설치 순서 (중앙 Pi 1대 + 작품 Pi 여러 대)

```text
① 중앙 Pi에 서버 설치 (한 번)  →  ② 각 Pi에 명령 한 줄 + 대시보드에서 '허용'  →  ③ 대시보드에서 Pi 카드에 작품을 끌어다 놓기
```

자세한 구조·통신 규칙은 [README](README.md). 여기는 순서만.

---

## 0. SD카드 굽기 — 모든 Pi 공통 설정값

Raspberry Pi Imager에서 OS 고르고 **"설정 편집(OS customisation)"** 에 이렇게 넣기:

| 항목 | 값 | 왜 |
| --- | --- | --- |
| OS | **Raspberry Pi OS (64-bit)** — 데스크톱 있는 버전 | Lite는 화면에 작품을 못 띄움 |
| 호스트 이름 | 중앙: `live-control` / 작품 Pi: `pi-01`, `pi-02` … | 겹치면 안 됨 |
| 사용자 이름·비번 | 전부 같게 (예: `pi` / 아무거나) | 관리 편함 |
| Wi-Fi | 전시용 공유기 이름·비번, 국가 `KR` | 중앙과 모든 Pi가 **같은 공유기**에 있어야 함 |
| 시간대 | `Asia/Seoul` | 로그 시간 |
| SSH | 켜기 | 모니터 없이 원격 확인 |

- 공유기는 인터넷 되는 것 (Gemini 써야 하니까). 관람객 Wi-Fi 말고 전시용으로 따로 쓰는 걸 추천
- 중앙 Pi는 가능하면 **랜선**으로 공유기에 꽂기

## 1. 중앙 Pi (딱 한 번)

1. 이 repo를 중앙 Pi로 가져오기 (둘 중 하나)
   - `git clone <저장소 주소> ~/inter` → 학생 폴더들도 같이 와서 대시보드 목록에 바로 뜸
   - 또는 USB로 `local-server` 폴더만 복사 → 작품은 대시보드에서 올리면 됨
2. 터미널에서:
   ```bash
   bash ~/inter/local-server/controller/install-central.sh
   ```
3. 끝나면 이렇게 나옴:
   ```text
   대시보드 (노트북·폰에서):  http://live-control.local:8700/?t=…
   새 Pi 추가:  curl -fsSL http://live-control.local:8700/join | bash
   ```
   - 대시보드는 같은 Wi-Fi의 노트북/폰 브라우저로 열기. 한 번 열면 다음부터는 `http://live-control.local:8700` 만 쳐도 됨
   - **토큰(`?t=…`) 들어간 주소는 단톡방에 올리지 말기**

- 재부팅해도 자동으로 켜짐. 주소 다시 보기: `bash ~/inter/local-server/controller/url.sh`
- 서버 로그: `journalctl -u live-control -f`
- 코드 업데이트: `git pull` 후 `sudo systemctl restart live-control` → 대시보드 "Agent 업데이트 (전체)"
- 맥을 중앙으로 쓸 때는 예전처럼 `sh local-server/controller/start.command`

## 2. 작품 Pi (Pi마다 한 번)

1. 마이크 · 스피커 · 2인치 화면을 꽂고 부팅
2. Pi 터미널에서 (둘 중 하나, 아무것도 안 물어봄, 5~10분)
   - 중앙이 켜져 있으면: `curl -fsSL http://live-control.local:8700/join | bash`
   - 파일로: `bash pi-setup.sh` — **중앙이 아직 없어도 됨** (파일은 중앙에서 `python3 local-server/controller/server.py --make-setup pi-setup.sh` 로 만들거나 받은 걸 USB 등으로)
3. 대시보드 위쪽에 **연결 요청**이 뜸 → 우리 Pi가 맞으면 **허용** (토큰 복사할 필요 없음)
   - 중앙이 나중에 켜져도 됨: Pi가 알아서 계속 찾다가 요청함
4. `sudo reboot`
5. 대시보드에 카드가 뜨면 이름 바꾸기 (예: `03-냥이`), 진행자 Pi 1대만 역할 `master`

설치 명령이 알아서 해주는 것: Chromium · 한글 글꼴 · 소리 도구 설치, agent 자동 실행(부팅 시 + 죽으면 재시작), 데스크톱 자동 로그인, 화면 꺼짐 방지, Wi-Fi 절전 끄기, 한국 시간

### 중앙 없이 이 Pi에서 바로 띄우기 — `live` 명령

설치하면 Pi에 `live` 명령이 생김. 중앙이 없어도 됨:

```bash
live                   # 지금 상태 (중앙 연결됐는지, 무슨 작품이 도는지)
live run ~/작품폴더     # 이 Pi에 있는 작품(폴더/zip/html)을 바로 전체화면으로
live key               # Gemini API 키 넣기 (중앙 대시보드에 키가 있으면 그게 우선)
live stop              # 끄기 (다시 켜기: live start, live restart)
live logs              # 로그
```

- 전체화면 작품이 화면을 덮어서 터미널이 안 보이면: **Ctrl+Alt+T** 로 터미널 열고 `live stop` (또는 다른 컴퓨터에서 `ssh pi@pi-01.local live stop`)
- 설치하면서 바로 띄우기: `bash pi-setup.sh ~/작품폴더`
- 나중에 중앙에서 이 Pi 카드에 작품을 올리면 그걸로 바뀜

### 손으로 해야 하는 것 (명령이 못 해줌)

| 할 일 | 방법 |
| --- | --- |
| **2인치 화면 드라이버** | 화면 모델마다 설정이 달라서 자동 불가. 이미 화면이 나오는 Pi의 `/boot/firmware/config.txt` 맨 아래에 추가한 줄(`dtoverlay=…`)을 똑같이 복사 → 재부팅. 드라이버 파일을 따로 깔았다면 그것도 |
| **스피커·마이크 고르기** | 대시보드 카드 → "설정 · 오디오 …" → 스피커/마이크 선택, 볼륨 → **적용** → **스피커 테스트**(띵동) / **마이크 테스트**(말하면서 누르기) → 작품 **Restart** |
| **API 키** | 카드 → "이 기기 API 키" (비우면 "공용 API 키"). 키 하나를 여러 Pi가 같이 쓰면 동시 접속 제한에 걸릴 수 있어서 Pi마다 따로가 안전 |

> **팁 — SD카드 복제**: Pi 1대를 화면 드라이버까지 완전히 세팅(설치 명령 포함)한 뒤 SD카드를 복제해서 나머지에 꽂아도 됨. 기기 구분은 보드 고유번호로 해서 대시보드에 따로따로 뜸. 복제한 Pi마다 이름만 바꾸기:
> `sudo raspi-config nonint do_hostname pi-02 && sudo rm /etc/machine-id && sudo systemd-machine-id-setup && sudo reboot`

### 점검 (Pi마다 1분)

카드의 프로젝트에서 **`예제 · pi-check`** 선택 → **Deploy** (Gemini 키 없어도 됨)

- [ ] Pi 화면에 기기 이름이 크게 뜸 → 화면 OK
- [ ] 초록 막대가 소리에 따라 움직임 → 마이크 OK
- [ ] **Identify** → 노란 화면 + 삑 → 스피커 OK
- [ ] 대시보드 **대화 시작** / **그만** → 화면 글자가 바뀜 → 쇼 신호 OK
- [ ] `sudo reboot` → 1~2분 뒤 카드가 다시 초록 + 작품이 저절로 다시 뜸

### 2인치 화면에 띄우기 (자동)

- 작품은 **각 Pi에서 제일 작은 화면(2인치)에 전체화면으로** 뜸. HDMI 모니터를 같이 꽂아 둬도 됨. 설정할 것 없음
- 확인: 대시보드 카드 둘째 줄에 `작품 화면: SPI-1 240×320` 처럼 보이면 정상 (이름은 화면마다 다름)
  - `— 2인치 화면이 안 보임`이 붙어 있으면 OS가 2인치 화면을 아직 모름 → 위 **2인치 화면 드라이버** 줄 확인
- 옆으로 누워 보이면: **전체 제어 → 2인치 화면 (전체) → 방향** 90° / 270° 중 맞는 걸로 저장 (한 대만 다르면 그 카드의 "2인치 화면 → 방향")
- 그래도 모니터에 뜨면: 같은 곳의 **"모니터는 끄고 2인치 화면만 쓰기"** 체크 → 작품이 켜질 때 모니터를 끔 (Stop 누르면 다시 켜짐)
- 카드에 `스피커: … · 마이크: …` 도 같이 보임. 마이크가 `없음`인 Pi는 소리를 못 들음

## 3. 작품 올리기 = 그 Pi 화면에 뜸

- 대시보드에서 **그 Pi 카드에 작품 폴더나 zip을 끌어다 놓기** (또는 카드의 "zip 올리기" / "폴더 올리기")
- → 중앙에 저장 → 그 Pi에 설치 → 전체화면으로 뜸. 진행 상황은 카드의 로그에
- 고쳐서 **같은 이름으로 다시 올리면** 새 버전으로 교체
- **Pi가 꺼져 있어도** 올려두면 켜지는 순간 자동 설치
- `.git`, `node_modules`, `.DS_Store` 는 자동으로 빠짐. `key.js` · `.env` 는 Pi로 안 보냄 (키는 대시보드에 넣은 걸로 Pi에서 새로 만듦)
- 실행 방법은 폴더 모양을 보고 추측함 (README "4) live.json"). 틀리면 폴더에 `live.json` 넣거나 카드의 manifest 칸에서 고치기
- 작품 코드 쪽 준비(키 파일, `persona.txt`, `live-bridge.js`)는 README **"4. 학생이 할 일"**

## 4. 안 될 때

| 증상 | 해결 |
| --- | --- |
| 설치 명령이 `Could not resolve host` | 대시보드 "새 라즈베리 파이 추가"의 **두 번째(IP) 명령** 사용 |
| 연결 요청이 안 뜸 / 카드가 안 뜸 | 그 Pi에서 `live` → "중앙을 찾는 중"이면 같은 Wi-Fi인지·중앙이 켜졌는지 확인. "옛 버전"이면 중앙에 새 코드 덮어쓰고 `sudo systemctl restart live-control`. 자세히: `journalctl -u live-agent -f` |
| 중앙을 새로 설치해서 토큰이 바뀜 | 그냥 기다리기 — Pi들이 알아서 다시 연결 요청함 → 허용 |
| 대시보드 주소가 안 열림 | 중앙 Pi에서 `bash ~/inter/local-server/controller/url.sh` → IP 주소로 |
| 공유기를 바꿔서 중앙 IP가 바뀜 | 그냥 기다리기 — Pi들이 중앙을 자동으로 다시 찾아감 (1분 안) |
| 작품이 큰 HDMI 모니터에 뜸 | Agent가 0.5.0 이상인지 (카드의 `v…`) → 아니면 "Agent 업데이트". 그래도 그러면 "2인치 화면 (전체)"에서 **모니터 끄기** 체크 |
| 카드에 `2인치 화면이 안 보임` | 2인치 화면 드라이버 설정(`config.txt`) 확인 → 재부팅. 그 Pi 터미널에서 `live` 치면 보이는 화면 목록이 나옴 |
| 소리가 엉뚱한 데서 남 | 카드 → 오디오에서 스피커 선택 → 적용 → Restart |
| 화면 한글이 □□□ | 설치 명령을 그 Pi에서 한 번 더 실행 (한글 글꼴) |
| `mic: no bridge` | 그 작품 페이지에 `live-bridge.js`가 안 붙어 있음 → 쇼에 참여 못 함 (README 4-3) |
